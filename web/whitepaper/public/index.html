Declining Hardware Cost Thresholds

A decade ago, AAA titles required flagship GPUs; today they run on mid-range hardware. Large language model inference appears to be following a similar commoditization curve.

Democratization of AI Access

Project Rationale

TKNC is not merely another cryptocurrency. It is a protocol-level project positioned at the intersection of two transformative trends: the commoditization of AI compute and the demand for decentralized infrastructure. Energy costs represent a significant constraint for centralized AI data centers. A decentralized architecture distributes energy demand across geographically diverse participants. Computing hardware has advanced by orders of magnitude over the past decade, and current high-end devices will likely appear modest by 2035 standards. The essence of traditional PoW

"Consuming energy for cryptographic security"

Bitcoin miners consume hundreds of millions of kWh a day, producing only a hash string. That hash string has no use value in itself.

The essence of traditional PoS

"Stake-based validation"

After Ethereum moved to PoS, it no longer needs compute — only staked ETH. The rich get richer, and network security relies entirely on the token price.

The essence of TKNC Dual-Mode

"Dual-purpose compute utilization"

When operating in PoW mode, TKNC nodes contribute to network security just as traditional PoW miners do. When inference requests arrive, the same hardware is repurposed to execute AI inference tasks — delivering tangible computational output rather than purely cryptographic work.

This means:

  • Same electricity spend → traditional PoW gets only a block reward
  • Same electricity spend → TKNC earns Coinbase when idle and inference fees when busy (double protection)
  • Diversified revenue model: inference income supplements mining rewards, potentially improving ROI stability

The dual-mode architecture represents a fundamental rethinking of blockchain utility. Unlike traditional PoW networks where energy expenditure serves only security purposes, TKNC redirects the same computational resources toward economically productive work when demand exists. This structural difference means the network's value is not purely speculative — it is backed by real computational output. As AI inference demand grows, this dual-purpose model could become increasingly compelling compared to single-purpose blockchain networks.

OpenAI-compatible API

API-compatible with the OpenAI interface format, enabling straightforward migration of existing applications.

Handshake Verification Protocol

Before inference begins, a handshake protocol verifies token counting consistency between client and miner. Both sides independently count test tokens; mismatches terminate the connection. This provides a basic defense against billing discrepancies.

Pay-Per-Use Billing Model

No upfront deposit required. Settlement occurs on-chain per usage.

GPU-Accelerated Architecture

GPU-only by default. Supports CUDA, Vulkan, and OpenCL backends. Refuses to start without a GPU.

Handshake Verification & Billing Integrity

A handshake mechanism is employed to verify billing consistency before inference commences:

Stage 1: Handshake request Client → Miner: HANDSHAKE_REQ { model, test_prompt }
Stage 2: Micro real inference Miner runs a micro inference (max 5 tokens) Miner → Client: HANDSHAKE_RESP { test_tokens[], token_count, wallet }
Stage 3: Client independent verification Client recounts test_tokens with the same tokenizer ├─ Count match → establish inference link ✅ └─ Count mismatch → reject connection ❌

Extra protection: price-consistency verification

  • Handshake returns the miner's real exchange ratio (computed independently by the node)
  • Client checks: web-listed price vs handshake actual price
  • Mismatch → popup warning for user confirmation, preventing bait-and-switch

Pay-Per-Use On-Chain Settlement

TKNC pay-per-use model:

Inference occurs → client node locally accrues spend → every full 1 TKNC → client wallet transfers on-chain to the miner

  • Funds never sit in any middle position
  • On-chain transactions are immutable. In the event of a connection interruption, at most < 1 TKNC of unsettled usage may be lost.
  • No consumption, no payment — no refund needed

GPU-Accelerated Architecture

  • GPU-only by default: supports CUDA, Vulkan, and OpenCL backends
  • Requires GPU acceleration by default; CPU-only mode requires explicit opt-in via -use-cpu flag
  • Avoids silent degradation: never "thinks it's on GPU while actually on CPU all day"
  • Model format: GGUF (llama.cpp native), supports quantized inference (Q4_K_M, etc.)

Rationale for Decentralized Architecture

Limitations of Centralized Platforms

Centralized AI platforms exhibit several structural limitations that warrant examination: (1) unilateral policy changes may disadvantage participants, (2) censorship risk may constrain legitimate expression, (3) custodial fund models introduce counterparty risk, (4) data concentration raises privacy concerns, and (5) geographic restrictions limit global accessibility. A decentralized architecture addresses these limitations through distributed consensus and cryptographic guarantees.

Centralized platforms: participants are subject to the platform operator's terms and policies.

The Decentralized Alternative

In a decentralized model: rules are encoded in protocol logic, enforced by network consensus, and executed without intermediaries.

Decentralized networks: participants contribute to and benefit from a shared infrastructure.

Three Core Properties of Decentralized Networks

🚫Censorship-resistant participation
❄️No single entity can unilaterally freeze funds
📜Protocol changes require network consensus

Cryptographic keys provide self-custody of funds and identity on the network.
